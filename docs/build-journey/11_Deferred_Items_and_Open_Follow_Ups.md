CLAUDE.md task entries, ADRs, and the Trade-offs Log — not a duplicate of any of them. Each item names
its current state and a concrete next step, not just a description of the gap. Read this before
picking the project back up; the source entries linked from each row carry the full evidence trail if
more detail is needed.

Last consolidated 2026-09-13 (Migration Plan Phase 11). Update this document as items close or new
ones surface — it goes stale the moment it stops being maintained, the same risk `00_Documentation_

## Design decisions raised this session, not yet acted on

| Item | Current state | Concrete next step |
|---|---|---|
| **A forced test report is reachable only within the browser session that created it** | Confirmed live (Migration Plan Phase 11 pre-work, 2026-09-13): `GenerateView`'s completed-cycle state (`cycleId`) lives in React component state only — a refresh or navigation loses it, and the report itself is permanently excluded from the report table by `is_test_fixture`. There is currently no way back to a forced report's download link once the session ends, short of knowing its `report_id` and calling the API directly. **Recommendation, not yet implemented:** accept this as-is rather than building a second visibility mechanism (a "test runs" admin view, or a browser-local list of recent forced report IDs) — either would reopen exactly the kind of duplicate-visibility-path this project's `is_test_fixture` design exists to avoid. The one real gap is that this is currently a silent side effect rather than a stated constraint. | Add one line to the existing pre-click disclosure banner in `GenerateView.tsx` (the same banner that already states the `is_test_fixture` consequence): "This report is reachable only from this screen, right now — download it before navigating away; there is no way back to it afterward." A copy change, not a new mechanism. |
