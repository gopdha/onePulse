# OnePulse — Trade-offs Log

Every entry here represents a deliberate choice to accept a real limitation in exchange for a real benefit — stated explicitly rather than left implicit. Each includes current status: still accepted, resolved, or open for reconsideration.

---

| # | Trade-off | What Was Gained | What Was Given Up | Status |
|---|---|---|---|---|
| 1 | Model: GPT-5-mini instead of Claude Sonnet/Haiku | Unblocked all development under real quota constraints | Claude's specific reasoning quality is unverified in this pipeline; the original model-tiering cost story was never realized | **Open** — real decision needed: pursue Claude quota/region fix, or adopt GPT-5-mini permanently |
| 2 | Scoped, time-boxed ADO PAT instead of resolving tenant-duality identity issue | Unblocked the entire ADO integration under real deadline pressure | A real, still-unresolved gap in the "proper" Managed-Identity-first authentication story for ADO specifically | **Open** — PAT remains in use; the underlying Entra-ID fix is real technical debt |
| 3 | Manual MCP bridge instead of Agent Framework's native `MCPStdioTool` | Avoided risk to the single most-proven piece of code in the project; sidestepped 3 confirmed compatibility bugs of unknown total extent | Slightly more integration code to maintain long-term; doesn't benefit automatically from future native-client improvements | **Accepted** — reassess if/when Agent Framework's MCP support matures |
| 4 | Deterministic Committed-Feature scoping instead of a smarter, adaptive summarization step | Solved both the cost and correctness problems at scale, with measured, repeatable results | Any work outside the `Committed` tag convention is invisible to OnePulse entirely — requires disciplined tagging hygiene in the source ADO project | **Accepted** — a real process dependency, not just a technical one |
| 5 | Streamlit (local-first) instead of Azure Static Web Apps | Fast, working, iteratively-redesigned UI reusing existing Python functions directly | No real cloud deployment yet; Physical Architecture's original UI hosting design remains unbuilt | **Superseded** by ADR-015/016. ASWA was never viable for Streamlit; React + FastAPI on Container Apps replaces both sides of this trade. |
| 6 | Background-threaded pipeline execution instead of staying single-threaded | Enabled live-ticking progress timers, a real demo-quality improvement | The project-switch cancellation guarantee changed character — no longer instant, bounded by in-flight work (~4-16.5s measured) | **Resolved** by migration plan Phase 3. Moving execution to a worker retires the threading and `contextvars` machinery entirely; the ~4–16.5s cancellation framing no longer applies. |
| 7 | RAG Chat Assistant scoped to Postgres archive only, never live ADO | Clean architectural boundary; avoids duplicating Investigation's job with less rigor | Cannot answer questions about the *very latest* ADO state if it postdates the most recent report | **Accepted** — matches the intended "ask about past reports" framing |
| 8 | Near-verbatim rendering of untracked-initiative text in the Tower View (no rephrasing LLM call) | Zero risk of the system inventing wording; no added cost/latency | Slightly less polished prose than a dedicated rephrasing step might produce | **Accepted** |
| 9 | RLS built on `reports` ahead of its originally Next-scope timeline | Real security posture proven earlier than planned, when explicitly requested | A documented, acknowledged deviation from the Build Plan's own scoping notes — flagged plainly rather than silently absorbed | **Accepted, explicitly flagged** |
| 10 | Declined `BYPASSRLS` grant for the Entra Administrator role | Avoided a standing privilege grant with real future risk (defeats RLS's guarantee the moment someone forgets it exists) and zero present benefit (confirmed via direct testing) | Admin-level troubleshooting on RLS-protected tables still requires routing through a working alternate path | **Accepted** |
| 11 | Declined transient `UPDATE` grant on `approval_records` to complete a test-data deletion | Kept the append-only guarantee completely untouched, even transiently | One old test report (`report_id=306`, and its predecessor `320`) remain in the database permanently, un-deletable through normal means | **Accepted** — the guarantee's integrity was judged worth more than tidy test data |
| 12 | Log file split from UI display (full technical detail relocated, UI shows curated summaries) | A genuinely demo-appropriate, non-technical progress view | Real-time visibility into individual tool calls is no longer available in the UI itself — must check the log file | **Superseded** by ADR-021. Container filesystems are ephemeral; logs move to Application Insights and Blob Storage. |
| 13 | Tower View health color uses fixed severity tiers (Green/Amber/Red) rather than percentage bands | Simple, defensible, consistent rule; real counts still convey scale within a tier | Two towers with very different flagged-item percentages (2% vs. 11%) can show the same color | **Accepted, explicitly documented as a stated design choice, open to revision** |
| 14 | Two real team-lead status decks prepared, but only one used as the live pipeline input for the demo | Kept the demo simple and predictable | True multi-deck ingestion (combining multiple team leads' updates into one investigation) remains unbuilt | **Open** — a real, deliberately deferred capability |
| 15 | React + FastAPI instead of Streamlit | Real multi-user auth, a durable execution boundary, a UI not fighting a rerun model, and a deployable system | The REST layer ADR-010 deliberately avoided must now be built — and it is the bulk of the work, not the React | **Accepted** — ADR-015 |
| 16 | Separate BFF and core API with no functional requirement demanding it | Hands-on learning of external vs internal ingress, service-to-service Managed Identity auth, and cross-process trace propagation; room to add services later | Every field change touches two services; two log streams to debug; two chained cold starts on a first request | **Accepted, explicitly for learning** — ADR-017 |
| 17 | Investigation extracted as a separate service | Independent scaling of the stage that is 80% of runtime; Node confined to one container; the ADO PAT's blast radius narrowed to one consumer | A network boundary between stages that were one function call; findings duplicated across two stores | **Accepted, evidence-backed** — ADR-019 |
| 18 | Schema-per-service rather than database-per-service | Real cross-access rejection enforced by database grants, at zero additional cost, promotable to separate servers later | Not the textbook isolation — one server remains a shared failure domain and a shared cost line | **Accepted** — ADR-020 |
| 19 | Queue-based coordination instead of synchronous calls | Runs survive restarts; KEDA scales on backlog; the user can close the browser mid-run | At-least-once delivery means duplicate processing must be designed for; poison messages and dead-lettering become real concerns that did not exist in-process | **Accepted** — ADR-019 |
| 20 | Polling for run status instead of server push | Any replica can answer, because state lives in Postgres; works with scale-to-zero; the closed-laptop case works for free | Up to three seconds of staleness; no push notification when a six-minute run finishes and the user has walked away | **Accepted** — ADR-021. Revisit if a completion notification (email or Teams) proves genuinely needed. |
| 21 | Cloud-deployed UI cancels the Postgres stop/start saving | The system becomes reachable from anywhere, which is the point of deploying it | The CA$12–15/month saving from stopping the database between sessions is largely forfeit, since it must be available whenever the app might be opened | **Accepted** — noted in ADR-016 |
